第一次使用内容后台

后台采用 Sveltia CMS。内容保存在你的 GitHub 仓库，发布后由 GitHub Actions 生成官网。

先完成一次设置

  1. 在仓库 Settings → Pages，把 Source 改成 GitHub Actions，保留域名 www.njuga.cn，并开启 Enforce HTTPS。不要在有证书警告的页面输入凭证。
  2. 在 Settings → Collaborators 检查写入权限，仅保留你本人；也检查已安装的 GitHub Apps。仓库权限是后台发布的权限依据。
  3. 在 GitHub Settings → Developer settings → Personal access tokens → Fine-grained tokens 创建令牌。资源所有者选择 longmaogithub，仓库仅选择 NJUGA-website，权限只需要 Contents: Read and write（Metadata 自动只读）。设置有效期并妥善保存。
  4. 打开后台，选择“使用访问令牌登录”，将令牌输入登录框。它不是 GitHub 密码，也不要发给聊天助手。

如何发布

  • 文章：新建条目，填写标题、作者、日期和分类，选择封面。填写正文则生成站内文章；只填写原文链接则跳转公众号等外部页面。
  • 活动：填写日期、状态、简介、封面和活动正文，原始通知链接可选。
  • 独立页面：发布图文专题，可选择加入顶部导航。网址为 page-标识.html。
  • 网站设置：修改首页标题、大图、协会简介和联系方式。
  • 图片：通过图片库或编辑器上传 PNG、JPG、WebP、GIF、AVIF；建议每张小于 2 MB。不支持上传整套可执行 HTML/JS 网站或视频托管。

点击发布后等待 发布任务变绿，通常需要几分钟。校验失败时线上仍保留之前的正常版本，可修改错误后重新发布。图片被文章使用时不要直接删除；发布后不要修改网址标识。

仓库是公开的。“在官网显示”关闭只控制官网展示，不让 GitHub 文件变成私有。未发布内容、图片和历史记录也不要放个人敏感信息。令牌会由 CMS 保存在当前浏览器；共用电脑用完请退出并清理此站点数据，遗失令牌请到 GitHub 撤销。

是否需要服务器？

不需要额外购买服务器、数据库或对象存储。官网和后台都是静态文件，GitHub 存储内容并负责权限验证，Actions 负责自动生成。你需要续费域名、更新到期令牌，以及偶尔检查依赖和发布任务；后台登录和上传需要能够访问 GitHub。
